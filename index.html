Groq Key Auditor

For developers juggling more than one Groq key

Know exactly what
each key can still do.

Paste your keys, run the audit, and see every key–model combination's status, rate limit, and remaining token budget, pulled live from Groq, in your browser.

How it works
01

Model discovery

For every key you paste, the tool calls /v1/models and pulls back the full list of models that key can reach, skipping embedding and Whisper models, since those aren't chat endpoints.

02

Concurrent testing

Each key–model pair gets a one-token test completion. Up to six run at once through a bounded worker pool, so a stack of keys clears in seconds instead of minutes.

03

Live usage data

Request and token counts come straight from Groq's rate-limit headers, with the response body as a fallback. Nothing is estimated: a dash means the data genuinely wasn't available.

Reading the results

Active

The key authenticated and the model responded with a 200. It's usable right now.

Limited

The key is valid but currently rate-limited (429). It'll work again once the window resets.

Dead

The request failed outright: revoked key, wrong scope, or the model isn't available to that key.

Nothing leaves your session

Keys are sent straight to Groq's API through a thin proxy that exists only to forward rate-limit headers browsers normally strip. Nothing is logged, stored, or sent anywhere else. Close the tab and the keys are gone.

Export when you're done

Every audit can be copied or downloaded as a CSV: key (masked), model, status, and usage counts, ready to drop into a spreadsheet or a ticket.

For developers juggling more than one Gemini key

Same audit,
for Google Gemini.

Paste your Gemini keys, run the audit, and see every key–model combination's status and token usage, pulled live from Google's Generative Language API, in your browser.

01

Model discovery

For every key you paste, the tool calls models.list and pulls back every model that supports generateContent — the Gemini chat models, skipping embedding and image/video-only models.

02

Concurrent testing

Each key–model pair gets a one-token test generation. Up to six run at once through the same bounded worker pool used for Groq, so a stack of keys clears fast.

03

Token usage

Token counts come from usageMetadata in the response body. Google's API doesn't expose remaining-quota headers the way Groq's does, so remaining columns show a dash — that's a Gemini limitation, not a bug.

Reading the results

Active

The key authenticated and Gemini returned a 200. It's usable right now.

Limited

The key is valid but currently rate-limited (429). It'll work again once the window resets.

Dead

The request failed outright: revoked key, wrong project, or the model isn't available to that key.

Nothing leaves your session

Keys are sent straight to Google's API through a thin proxy that exists only to handle CORS, since Google's endpoint doesn't allow direct browser calls with a JSON body. Nothing is logged, stored, or sent anywhere else.

Export when you're done

Every Gemini audit can be copied or downloaded as a CSV: key (masked), model, status, and token counts, same format as the Groq export.
